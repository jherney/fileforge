## Problem Statement
FileForge converts files through a local web page. The owner left online converter sites for privacy and wants conversion to need no browser at all: drop a file in a folder, get the converted file back.

## What Makes This Cool
The web page disappears. A folder named for the target format (`~/Convert/to-pdf/`) is the whole interface. The owner's words: "Magic folder + auto-convert", with no browser.

## Constraints
- One user, local machine, Linux (Fedora/KDE), nothing leaves the machine.
- No new dependency if avoidable (polling instead of `watchdog`).
- Originals are never deleted or overwritten.

## Premises
1. The pain is the friction of one-off conversions; a folder that converts on drop removes the ritual. (agreed)
2. Do not chase format breadth: ConvertX (1000+ formats) and HRConvert2 already exist; the edge is local, simple, automatic. (agreed)
3. The watcher reuses `REGISTRY` in `app.py` directly, with no HTTP round trip. (agreed; the cold read challenged it, but `app.py` converters are plain bytes-to-bytes functions with no request state, and each LibreOffice call uses its own temp profile, so it holds)
4. Single user, so a hand-started Python process is enough; a systemd user service comes later. (agreed)

## Cross-Model Perspective
Codex was unavailable (401, no credentials); a fresh-context Claude subagent gave the cold read (same model family, so agreement is weak evidence).
- Coolest version: each subfolder is a pipeline, with chains (heic to jpg to resized to searchable PDF), a Results page with undo and re-run, and desktop notifications.
- What excites the owner: "no browser"; they want the web UI to disappear.
- 50% there: `watchdog` or `inotifywait` plus the existing `REGISTRY`. The 50% to build: fully-written detection, folder-to-target mapping, collision-safe names, error log, chaining.
- Weekend build: `watcher.py`, stable-size wait, lookup in `REGISTRY`, write to `out/`, log JSONL, `notify-send`, failures to `failed/` with an `.err` file.

## Approaches Considered
### Approach A: Subfolder watcher script (chosen)
One new file, `watcher.py`. Effort S. Risk low. Reuses `REGISTRY`.
### Approach B: Rules engine with chains and a Results page
Ruled out for now: much larger surface for a one-person tool. Chains can grow out of A later by path-finding over `REGISTRY`.
### Approach C: Right-click "Convert to..." KDE service menu
Ruled out for now: not automatic. A good later addition on the same converter core.

## Recommended Approach
A. It is the fewest files and fastest to something usable tonight, and it keeps the door open for chains.

## Open Questions
- Where should output land: next to the input in `out/`, or back in the folder root with a new extension?
- Should originals move to `done/` or stay put? Default in this design: copy, never move or delete.
- Does `.heic` need a Pillow plugin (`pillow-heif`)? Currently unsupported by `IMAGE_SOURCES`.

## Success Criteria
- Dropping `report.docx` into `~/Convert/to-pdf/` produces `report.pdf` in `~/Convert/to-pdf/out/` within about 10 seconds, with the original untouched.
- A file still being copied is not converted half-written.
- An unsupported pair or failed conversion leaves the original in place and writes a readable `.err` file; the watcher keeps running.
- Two files dropped at once both convert (LibreOffice runs do not collide).

## Distribution Plan
Runs from the repo as `python3 watcher.py`; no packaging. Auto-start via a systemd user service is deferred.

## Next Steps
1. Extract the converter lookup into a small function the watcher can call (`REGISTRY[(src, dst)].run(bytes)`); confirm it runs from a plain script while the server is also converting.
2. Write `watcher.py`: poll `~/Convert/to-<fmt>/` every 2 seconds, treat a file as ready when its size is unchanged across two polls, ignore `.part`, `.crdownload` and dotfiles.
3. Convert via `REGISTRY`, write `out/<name>.<fmt>` with collision-safe naming, log one JSON line per job, send `notify-send` on success or failure.
4. Test: half-copied file, two simultaneous drops, unsupported type, same name twice.
5. Later: systemd user service, chains via path-finding over `REGISTRY`, KDE right-click menu.
